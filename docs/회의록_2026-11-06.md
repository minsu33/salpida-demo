# 회의록 · 시연 앱 고도화 (2026-11-06)

참석: 기획(PM), 디자인, 프론트엔드, 백엔드·데이터. 각자 현재 코드(src/)를 읽고 의견서를 냈다.

## 모두 같은 의견
- 업장 상세의 정보 순서가 거꾸로다. 신뢰 정보(영업 상태·확인일·출처)가 맨 위로, 행동 버튼은 하단 고정으로.
- 주황은 행동 버튼에만. 선택된 핀·토글·선택한 답은 검정으로.
- 화면 전환에 방향이 없다. 들어갈 때와 뒤로 갈 때 반대로, 탭 전환은 페이드.
- 로딩(스켈레톤)·빈 상태·오류 상태가 없다. mock API로 지연을 만들어 보여 준다.
- 홈 화면 앱에서는 ?reset을 못 쓴다. 숨은 시연 모드가 필요하다.

## 기획이 짚은 핵심
- 알림을 받고 나서 "그래서?"가 된다. 알림에 '지금 할 일'(남은 금액, 할부 멈춤 요청 안내, 환불 요청 문구)을 붙여야 실용성이 보인다.
- 결제 전 체크가 설문처럼 보인다. 카운터에 보여 주는 화면(큰 글씨 질문)이 있어야 한다.
- '보장 업장'이 광고처럼 보일 수 있다. 공공데이터 정보와 보장 표시는 자리를 나눈다 (Yelp는 광고와 경고를 분리).
- 시연은 1분, 장면 6개.
- '바디핏'은 실제 상호와 겹칠 수 있다.

## 디자인 제안
- 지도 핀 이름표에 크기("작은 편"), 바텀시트 끌기(반·전체), "상세 보기" 버튼.
- 글자 크기 12/14/16/20/26/40 여섯 단계로 통일.
- 업장 기록의 "글 0건" 달을 더 눈에 띄게.

## 프론트 제안
- 파일 분리(screens/, components/, lib/), useReducer + Context, history와 연결한 스택 내비게이션.
- framer-motion 도입(전환·바텀시트·스프링). react-router·zustand는 쓰지 않음.
- 핀 좌표를 퍼센트로(지금은 402px 기준이라 실기기에서 어긋남).
- iOS: safe-area 일관 적용, 스크롤 바운스 막기, 폰트 직접 서빙.

## 백엔드·데이터 제안
- 실제 인허가 데이터를 동 1곳만, 상호는 가리고(○○휘트니스 A점) 면적·업력·보험 여부는 실제 값으로. 좌표는 약 100m 단위로 흐림.
- src/api.js mock 레이어(지연, ?fail 오류), 화면은 api만 거침.
- 발표용 실제 아키텍처: 인허가 주 1회 수집 → 변경 감지 → 웹푸시, 블로그는 집계 신호만 저장.

## 1분 시연 시나리오 (안)
| 시간 | 장면 | 보여 줄 것 |
|---|---|---|
| 0~6초 | 자막: "남은 이용권 48만 원" | 문제 공감 |
| 6~16초 | 지도 → 업장 상세 | 크기만 봐도 차이 (작은 편 약 2배) |
| 16~30초 | 체크 → '모름' → 카운터에 보여 주기 | 물어볼 말을 대신 챙겨 줌 |

| 38~52초 | "3개월 뒤" → 푸시 → 알림 + 지금 할 일 | 결제 후에도 지켜 줌 |
| 52~60초 | 업장 기록 그래프 | 세 번 알려 주는 구조 |
